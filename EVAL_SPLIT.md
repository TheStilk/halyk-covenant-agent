# Разделение train / holdout — зафиксировано 2026-08-06

**Этот файл менять нельзя.** Состав holdout выбран один раз и не перевыбирается
ни при каких результатах. Пересдача holdout после того, как цифра не понравилась, —
самый частый способ вернуть себе публичные 98.6% другим путём.

## Состав

```
HOLDOUT (12 ячеек):  B4, P10, P2, P6
TRAIN   (24 ячейки): B1, P1, P3, P4, P5, P7, P8, P9
```

## Правило отбора

Holdout обязан состоять только из сценариев, **никогда не использовавшихся как цель
оптимизации**. Иначе метрика на holdout завышена по построению и не оценивает
перенос на приватные данные.

Засвеченные сценарии выявлены из истории репозитория и рабочих заметок:

| Сценарий | Где засвечен |
|---|---|
| `P4` | `1c5538c` «P4/6.1 adjusted EBITDA margin to 0.33»; `fa15901` «P4/6.3 max-ratio status»; `ZHENIS.md` (7 упоминаний) |
| `P7` | `fa15901` «P7/6.1 fill NaN ledger tax from treasury memo» |
| `P3` | `fa15901` «P3/6.1 FX-convert EUR servicing» |
| `P8` | `fa15901` «P8/6.1 avoid double-counting filled payroll» |
| `P1`, `P5`, `B1` | `ZHENIS.md` — «работающие ячейки не трогать» (значит, сверялись с ключом) |

Чистый пул: `B4, P10, P2, P6, P9` (5 сценариев).
Из него: единственный доступный `B`-сценарий (`B4`) + 3 `P` жребием с фиксированным
зерном `random.Random(20250809)`, чтобы состав нельзя было подобрать.

Стратификация по `B`/`P` нужна потому, что `B1`/`B4` сидят на счетах `ACC-7201`/`ACC-7204`
— отдельное семейство нумерации против `ACC-78xx` у всех `P`.

## Как пользоваться

- При любых правках кода holdout **не открывается**: ни ответы, ни поячеечная разбивка.
- Эталонные `CovenantSpec` (Пункт 5 плана) пишутся **только по train**.
- Метрика для сравнения веток 8 августа считается **только на holdout**.

## Оговорка, которую нельзя забыть при сравнении веток

Для **старого детерминированного движка holdout не является честной отложенной
выборкой ни в каком виде.** Его 20 обработчиков формул (`formula_engine.detect_formula_id`)
построены просмотром всех 36 публичных ячеек — то есть движок видел и holdout тоже,
просто не поимённо в коммитах. Его результат на holdout — **верхняя граница**, а не оценка.

Для агентной ветки holdout честный: агент не использует обработчики формул, а
эталонные спеки по holdout не пишутся.

**Следствие для гейта 8 августа.** Критерий «агент не хуже старого движка на holdout»
смещён против агента: сравниваются честное число и завышенное. При равенстве или
отставании агента в пределах ~1 ячейки предпочтение отдаётся агенту, а не старому
движку, — потому что на приватных данных завышение старого движка исчезнет, а
агентное число останется тем же.

Единственный способ измерить старый движок честно — сценарии, которых нет ни в
публичном наборе, ни в его настройке. Таких у нас нет до 9 августа.
