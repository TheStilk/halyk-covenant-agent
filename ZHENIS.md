## 3. Порядок работы

### Шаг 1. Unknown covenant fallback

**Проблема:** на private set почти наверняка будут новые формулировки ковенантов, которых нет в `formula_engine.py`.

**Задача:**
1. Найти, как сейчас обрабатывается «неизвестный» тип ковенанта
2. Спроектировать безопасный fallback:
   - если formula engine не распознал тип → LLM Formula Reader (formula_spec) + code compute
   - на вход: текст ковенанта + compact metrics
   - на выход: formula_spec → actual/status (LLM не считает арифметику)
3. Fallback должен включаться **только** когда детерминированный путь не сработал
4. Не менять поведение на уже закрытых 36 ячейках open set

**Сдать:**
- краткий дизайн fallback
- какие функции/файлы менять
- пример промпта для LLM-fallback

---

### Шаг 2. Missing amounts / NaN в ledger

Уже были кейсы:
- `TXN-P7-0033` — amount=NaN, сумма нашлась в treasury memo
- `TXN-P8-0031` — похожая ситуация

**Задача:**
1. Описать текущий механизм `missing ledger fills`
2. Предложить более общий recovery:
   - поиск суммы по `txn_id` в PDF
   - поиск в memo / AUP / notes
   - явный warning, если amount так и не найден
3. Минимальный патч без поломки текущих fills

**Сдать:**
- алгоритм recovery
- где в коде это лучше встроить
- какие edge-cases учесть
